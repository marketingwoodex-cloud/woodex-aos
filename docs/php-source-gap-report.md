## 5. Why the PHP admin cannot simply be started here

1. **No PHP interpreter and no MySQL server.** `which php mysqld mariadb mysql` returns nothing, and there is no package manager access (`apt` is unreachable). Only `registry.npmjs.org`, `pypi.org`, `files.pythonhosted.org`, `github.com` are reachable.
2. **The archive cannot be fetched by URL.** `curl https://drive.google.com/uc?export=download&id=1plK…` fails (TLS connection refused); `google.com` also fails. Egress is allow-listed.
3. **The connector path is impractical for 94 MB.** The Drive connector can read the file, but it returns file bytes inline as base64 (~126 MB of text). That cannot pass through a tool result.
4. **Even with PHP, the code expects MySQL.** `php-wasm` *is* installable from npm (`@php-wasm/node` 3.1.64), so PHP itself could execute in Node — but that build ships **without `mysqli` / `pdo_mysql`**, and there is no MySQL server to talk to. The PHP app would have to be adapted: either a `mysqli`-compatible shim class over SQLite, or a Node MySQL-protocol emulator in front of SQLite.

Consequence: running the **unmodified** PHP admin is not possible in this sandbox. The realistic options are in §7.

## 6. What the audit already established about this data

- Dump imports cleanly: 41 tables, 637 rows, 0 SQL errors; only 1 foreign key in the whole schema.
- Catalogue layer is sound: unique slugs, 3-level tree with no inconsistencies, valid JSON in `specs`/`images`, no orphan category links.
- All money reconciles: orders 12,610,000 · quotations 1,793,301 · POS totals match their line items.
- **The damage is referential:** products were re-imported so their IDs moved to 34–207 while history still points at 1–32 → 6/6 order items, 5/5 variations, 15/25 quotation lines, 5/5 POS items, 3/3 reviews and 13/13 product FAQs are orphaned.
- Also: 10 duplicate + 26 blank + 82 `SKU:`-prefixed SKUs, 34 products with price 0, 135 of 171 out of stock, 25 latin1 vs 16 utf8mb4 tables, no audit/session/migration tables, one admin account.

A PHP admin running on this same dump would show the same broken product links in orders — the problem is in the data, not in the code or in our preview.
